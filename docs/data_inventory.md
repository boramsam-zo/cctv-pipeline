### 출처와 다운로드 상태

- 사고 파일을 찾을 곳: 사용자 제공 [ACCIDENT Kaggle 배포](https://www.kaggle.com/datasets/picekl/accident)의 `real_videos`. 이번 웹 조회에서는 본문/파일목록/용량을 읽지 못했다. 위 이름은 **로컬 원본 CSV 근거**이며 원격 파일의 현재 다운로드 가능성을 확인한 것은 아니다. 찾을 수 없으면 이름을 바꾸어 맞추지 말고 배포 파일 목록/버전을 알려준다. 파일 크기는 미확인이다.
- 정상 후보 우선 출처: [TADBench 제작팀 페이지](https://github.com/UnicomAI/UnicomBenchmark/tree/main/TADBench). 여기서 연결한 [TAD-benchmark.zip](https://drive.google.com/file/d/14GNlNcWLzN-sbzvmrMuSbAg_rZZ5yd26/view?usp=drive_link)의 이름은 확인했지만, 공개 미리보기에서 ZIP 용량·내부 개별 파일·공식분할·상세 이용 조건은 확인하지 못했다. 사고/무사고 모두 제공하는 출처를 고른 이유는 출처와 클래스가 완전히 일치하는 구성을 줄이기 위해서다. 이 자료가 ACCIDENT와 사건이 겹치지 않는다는 보장은 없으므로 중복 근거는 별도로 확인한다.
- 사용자가 허용된 다른 실제 고정 CCTV 원본을 이미 가지고 있다면 정상 후보를 그 자료로 대체할 수 있다. 그 경우에도 정확한 파일명·출처/사용 근거·촬영 회차/카메라 정보를 받아 목록을 고정한다. 객체 검출 주석이나 파일의 ‘normal’ 이름만으로 정상 정답을 만들지 않는다.
- 기존 QMUL Junction의 다른 시간대는 제외한다. 제작자 페이지의 Roundabout/Junction2 링크도 이번에 확인했으나 대상 페이지 접근이 되지 않아 개별 파일·용량·독립성 근거를 확보하지 못했다. AI Hub 소개 접근도 시간 초과였다. SO-TAD는 기존 약27.3GB 분할압축 안내만 있고 이번 개별파일 확인이 안 되어 이4원본 소량 확보의 우선 대상으로 삼지 않는다.
- **다운로드/압축 해제0회.** 현재 대상은 사고2파일과 정상2원본 후보이나 실제 전송 바이트 규모가 미확인이다. 규모 없는 전체 ZIP 다운로드 승인을 요청하지 않는다. 사용자가 배포 페이지에서 용량·개별 목록·이용 조건을 확인해 주면 정확한 대상/바이트/압축 해제 공간을 제시한 뒤 별도 승인받는다. 원본을 임의로 재인코딩하거나 잘라서 제출할 필요는 없다.

## 2. CSV 구조와 연결 키

CSV는 헤더 1행과 데이터 **2,027행, 22컬럼**이다. `path` 값은 2,027개로 모두 서로 다르며, 빈 키·빈 값·행 너비 오류는 발견되지 않았다. 이는 **이번 로컬 CSV의 구조 검사 결과**이며, 전체 영상 확보·영상 내용 중복 부재의 증거는 아니다.

연결 규칙은 `data/local/accident/` + CSV의 `path`를 그대로 결합하는 것이다. 파일명 일부, 접두사, 행 순서로 추측해서 연결하지 않는다. 아래 CSV 행 번호는 헤더를 1행으로 센 번호다.

| 선택한 원본 상대 경로 | CSV 행 | 매칭 수 | 파일 크기 |
|---|---:|---:|---:|
| `real_videos/-9oifpjUxxM_00.mp4` | 1408 | 1 | 2,483,706 bytes |
| `real_videos/-PpBteU0p3Q_00.mp4` | 785 | 1 | 1,740,108 bytes |

### 실제 컬럼과 해석 범위

아래의 값 예시는 로컬 CSV에서 읽었다. 의미는 로컬 관찰과 공식 설명을 구분했다. 로컬 사본에는 컬럼별 상세 명세가 없으므로 확인되지 않은 관례를 임의로 고정하지 않았다.

| 실제 컬럼 | 값·의미와 확인 상태 |
|---|---|
| `path` | 데이터 루트에 대한 영상 상대 경로. 선택 3개에서 정확히 매칭 확인. |
| `type` | 충돌 유형 문자열. 실제 값은 `head-on`, `rear-end`, `sideswipe`, `single`, `t-bone`. 사고/정상 이진 정답이 아니다. |
| `rollover` | `0`, `1`. 공식 논문은 전복 속성이라고 설명한다. 사고 유무로 사용하지 않았다. 0/1의 명시적 코드북은 로컬에 없다. |
| `accident_time` | 사고 시점. 공식 논문의 시간 정답은 클립 내 초 단위이며, 이번 검사는 그 근거를 명시해 seconds로 비교했다. 아래 프레임 정렬 한계 참조. |
| `accident_frame` | 사고 프레임 인덱스. 초 단위·화면에 표시된 원본 시각과 다르다. 0/1 시작 인덱스와 로컬 파일의 정확한 PTS 대응은 미확인. |
| `center_x`, `center_y` | 사고 위치의 중심 좌표. 선택 샘플 값은 0~1 범위이며 아래 박스의 중점과 일치한다. 픽셀 좌표나 위경도가 아니다. |
| `x1`, `y1`, `x2`, `y2` | 사고 관련 박스의 두 모서리 좌표. 선택 샘플은 0~1 범위이고 모서리 순서도 일관적이다. 정규화 좌표 해석은 공식 설명과 일치하지만, 로컬 좌표 원점·축 방향에 대한 별도 명세는 없다. |
| `region` | 지역 태그. 실제 20종에는 `Virginia`, `Iowa`, `Alabama`, `USA`, `World`, `Unknown` 등이 섞여 있다. 국가/주/도시가 통일된 지리 ID나 사건 ID가 아니다. |
| `scene_layout` | 도로·장면 태그 8종: `city_street`, `grade_separated_intersection`, `highway`, `parking_lot`, `roundabout`, `signalized_intersection`, `simple_intersection`, `tunnel`. |
| `weather` | 날씨 태그 `normal`, `rain`, `snow`. **여기의 normal은 정상 교통/무사고 정답이 아니다.** |
| `day_time` | `day`, `night`의 조명·주야간 태그. 날짜나 원본 촬영 시각이 아니다. |
| `quality` | `Very_Poor`, `Poor`, `Fine`, `Good`, `Excellent`. 품질 태그이며 구체적 등급 기준은 미확인. |
| `no_frames` | 프레임 수로 보이는 메타정보. 3개 모두 영상 헤더 프레임 수보다 1 작다. 총개수인지 마지막 인덱스인지, 전처리 기준이 다른지는 미확인. |
| `duration` | 영상 길이 메타정보. 초로 비교하면 스트림 길이와 약 0.03~0.04초 차이가 있다. 아래 실제값 참조. |
| `height`, `width` | 픽셀 단위 해상도. 선택 3개 모두 디코더 해상도와 일치. |
| `split_in_distribution` | 제공 CSV의 IID 분할 값은 `train`/`test`. 선택 3개는 모두 `test`. |
| `split_geo_aware` | 제공 CSV의 지리 분할 값은 `train`/`test`. 선택 3개는 모두 `test`. |

충돌 유형·전복 속성·사고 시점·사고 위치라는 해석은 [공식 논문 §3.1](https://arxiv.org/html/2604.09819v1#S3.SS1)에 근거한다. 시간 정답의 초 단위는 [§5.1](https://arxiv.org/html/2604.09819v1#S5.SS1)에 명시되어 있다. 이 설명이 로컬 사본의 프레임 번호 관례까지 검증한 것은 아니다.

| `-SNFUobKjoM_00.mp4` | `t-bone` | 13.533 | 403 | 30.0 | 897 | test / test |

세 행 모두 `rollover=0`, `weather=normal`이다. 이는 전복·날씨 정보다. 정상 영상이라는 뜻으로 변환하지 않았다.

시간값은 각 영상 길이 안에 들어온다. `accident_time - accident_frame / average_fps`는 각각 약 **0.036521초, 0.020796초, 0.039830초**다. 숫자 크기는 초 단위 해석과 부합하지만, 프레임 인덱스 시작점·삭제 프레임·시간 기준을 입증하지 못한다. `no_frames`에 1을 더하거나 시간값을 보정하지 않았다.

| 라벨 수준 | 확인 결과 |
|---|---|
| 영상 전체 사고/정상 이진 정답 | 명시된 컬럼·정상 클래스가 없음. 사고 주석이 붙은 3개이지, 별도 검수한 영상 이진 정답표는 아님. |
| 사고 시점 | `accident_time`, `accident_frame`에 한 지점이 있음. 정확한 프레임 대응 관례는 미확인. |
| 사고 시작·종료 구간 | 없음. 시점 주변 ±N초를 정답 구간으로 생성하지 않음. |
| 충돌 유형 | `type`의 5개 사고 종류. 이진 정답으로 이름만 바꾸지 않음. |
| 화면 내 사고 위치 | 중심과 박스 좌표 있음. 객체 추적 ID·모든 프레임의 박스는 없음. |
| 원본 촬영 시각·잘라낸 시작 오프셋 | 대응 컬럼/자료 없음. 클립 시간에서 원본 시각으로 환산 불가. |

## 5. YAML의 정의와 적용 대상

실제 구조는 최상위 `names` 아래 **정수 ID → 문자열 이름 24개**다. ID는 0~22와 29이며 23~28을 새로 채우지 않았다.

```text
0 Unlabeled, 1 Roads, 2 SideWalks, 3 Building, 4 Wall, 5 Fence,
6 Pole, 7 TrafficLight, 8 TrafficSign, 9 Vegetation, 10 Terrain,
11 Sky, 12 Pedestrian, 13 Rider, 14 Car, 15 Truck, 16 Bus,
17 Train, 18 Motorcycle, 19 Bicycle, 20 Static, 21 Dynamic,
22 Other, 29 Van
```

[공식 대회 데이터 설명](https://www.kaggle.com/competitions/accident/data)은 같은 이름의 YAML을 **합성 세그멘테이션 출력의 클래스 ID 표**로 설명한다. 로컬 파일에는 대상 폴더·영상·마스크 경로나 적용 버전이 지정되어 있지 않다. `metadata-real.csv`에도 이 YAML이나 마스크를 참조하는 컬럼이 없다. 따라서 이 사본을 실제 영상의 픽셀 정답 또는 사고/정상 클래스 표로 적용할 근거가 없다.

`Unlabeled`는 이 클래스 표의 항목이며 정상 영상 정답이 아니다. CSV의 `type` 문자열과도 다른 분류 체계다. 합성 영상·합성 CSV·마스크 파일 자체는 읽지 않았다.

## 6. 정상 자료, 실제/합성, 사건 그룹, 공식 분할

- **정상 자료:** 이번 3개는 사고 시점·유형 주석이 있는 영상이다. 제공 CSV의 `type` 값에도 정상 클래스가 없다. 검수된 정상 CCTV 영상이나 무사고 구간 정답을 확인하지 못했다. 전체 데이터에서 정상 자료가 전혀 없다고 단정하지 않는다.
- **실제/합성:** `metadata-real.csv`와 `real_videos/`라는 제공 경로, 공식 자료의 real CCTV 설명이 일치한다. CSV 자체에는 행별 real/synthetic 플래그가 없다. 영상 출처·제작 이력의 개별 진위 감사는 하지 않았다.
- **파일/원본/사건 ID:** `path`는 파일 키다. 별도 원본 URL, 원본 ID, 사건 ID, 재편집 그룹, 자른 시작 오프셋 컬럼이 없다. `*_00` 등 파일명 패턴을 사건 ID로 확정하지 않았다. 2,027개의 서로 다른 경로가 2,027개의 서로 다른 사건임을 뜻하지 않는다.
- **분할:** 로컬 CSV의 `split_in_distribution`, `split_geo_aware`를 그대로 보존했다. 두 컬럼 모두 실제 값은 train/test이며 validation 값은 없다. [공식 논문 §4](https://arxiv.org/html/2604.09819v1#S4)는 IID와 지리 분할을 설명한다. 이 로컬 파일의 릴리스 버전·분할 생성 스크립트까지 확인한 것은 아니다.
- **샘플 3개 모두 test:** 다음 학습·튜닝용으로 자동 이동하지 않는다. 별도 train 자료와 사건 그룹 기준의 validation 구성이 필요하다. 최종 테스트는 모델 선택·임계값 조정에 사용하지 않는다.
- **출처 버전 주의:** 사용자 출처는 [Kaggle 데이터셋](https://www.kaggle.com/datasets/picekl/accident)이다. 이 페이지는 브라우징 도구에서 본문을 읽을 수 없었다. 대회 페이지의 `labels.csv`/`test_metadata.csv` 배치를 로컬 `metadata-real.csv` 구조로 치환하지 않았다. 웹 설명은 의미 확인의 보조 근거이며 실제 로컬 구조와 구분했다.
- **이용 조건:** 지정 폴더에 라이선스·영상별 이용 허용 근거는 없다. 가공·공유 허용 범위는 미확인으로 남긴다.

## 7. 재실행 방법과 오류 구분

프로젝트 루트에서 실행한다. 검사기는 자동 파일 선택·다운로드·원본 쓰기를 하지 않는다. `--video`를 생략하면 실행하지 않으며 최대 3개만 허용한다. 아래 환경 생성은 최초 1회이며 이미 있는 환경에는 재실행하지 않아도 된다.

검사 의존성이 없는 환경에서도 CSV 검사와 의존성 미설치 상태 보고는 가능하다. YAML·영상 검사를 실제 완료하려면 검사 요구 패키지를 준비해야 한다. 데이터가 없으면 `file_missing`, 메타정보를 읽지 못하면 `metadata_unavailable`을 기록한다.

| 상태 | 의미 |
|---|---|
| `unique` / `missing` / `ambiguous` | 선택 영상의 CSV 매칭 1개 / 없음 / 여러 개. |
| `file_missing`, `access_denied`, `file_unreadable` | 선택 입력 없음 / 읽기 권한 없음 / 파일 읽기 실패. |
| `tool_missing` | PyAV 또는 PyYAML이 없어 해당 검사 미실행. |
| `media_open_or_decode_failed`, `no_video_stream` | 손상·미지원·디코더 실패 등 / 비디오 스트림 없음. 상세 오류 유형도 기록하며 손상 원인을 단정하지 않음. |
| `decode_timeout` | 영상당 20초 제한 초과. 정상 예측이 아님. |
| `time_unit_unverified` | 단위 근거를 지정하지 않음. FPS로 단위를 추정하거나 초로 자동 변환하지 않음. |
| `checked_with_warnings` | 파일 검사는 완료했으나 메타정보 차이·단위 미확인 등이 남음. 종료 코드 0, 경고는 JSON에 남음. |
| `needs_attention` / `invalid_request` | 필수 입력·검사 실패 / 범위를 벗어난 요청. 종료 코드 2. |

검사 출력에는 예측·사고 점수·생성한 정상 정답이 없다. `artifacts/s0/`의 실행 결과는 Git 제외 대상이다.

## 9. 다음 기준 모델 실험에 필요한 최소 자료

1. **검수된 사고/정상 정답과 정상 CCTV 영상:** 영상 전체 또는 구간 중 정답 단위를 정하고, 판단 불가 표본을 구분해야 한다. 정상 클래스 학습과 오탐 평가는 실제 무사고 정답이 있어야 가능하다. 미주석 구간·사고 전후 구간을 자동으로 정상으로 만들지 않는다.
2. **학습용 사고 자료와 분리된 검증 자료:** 현재 test 샘플과 구분된 train 자료, 원본/사건/재편집 그룹 대응표, 고정 분할 목록이 필요하다. 정상 영상에도 같은 분할·출처 기준을 적용해야 한다.
3. **시간·프레임 주석 정의:** 0/1 시작 인덱스, `no_frames`의 정확한 뜻, 재인코딩·중복 프레임 제거 이력, 원본 오프셋을 확인해야 한다. 구간 모델을 선택한다면 시작·종료 라벨 또는 검수된 구간 생성 규칙이 추가로 필요하다.
4. **출처/버전/이용 조건:** 실제 사용하는 로컬 사본과 대응하는 README·릴리스 식별자·이용 조건을 보관해야 한다.

이 자료와 정답 단위가 확인된 뒤 사용자가 S1 범위를 요청하면 데이터 정의·분할·전처리를 진행한다. 기준 모델 후보 선정·다운로드·학습은 이번에 수행하지 않았다. 3개 샘플의 결과로 전체 데이터 비율이나 모델 성능을 추정하지 않는다.
