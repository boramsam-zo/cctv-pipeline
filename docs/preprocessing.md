## 현재 결과

**코드 구현과 실제 3개 샘플의 미리보기 생성은 완료했다. 실제 샘플의 승인된 이진 정답은 아직 없다.** 라벨 정책은 `draft-0.1`이고, 샘플별 사고/정상 판정·검수자·정확한 승인 구간 기록은 없다. 작업 단계의 승인과 개별 샘플 정답의 승인을 구분했다.

실제 실행 결과는 `prepared_labeled=0`, `unconfirmed=3`, `error=0`이다. 세 샘플의 `target`은 모두 `null`이고, 학습용 입력 배열은 저장하지 않았다. 사고 시점·유형을 사고/정상 정답으로 변환하지 않았다.

이번 실행은 [라벨 기준 문서](label_policy.md)의 검토 위치 예시를 사용한 **라벨 없는 전처리 확인**이다. 앞뒤 1초가 검증된 사고 구간이나 최종 모델의 입력 길이라는 뜻은 아니다.

## 코드와 입력

| 파일 | 역할 |
|---|---|
| `src/boram3_cctv/preprocessing.py` | 구간·승인 기록 검증, PTS 기반 선택, 전체 화면 리사이즈, 배열·미리보기 저장 |
| `scripts/preprocess_samples.py` | 입력 목록 읽기, 샘플별 별도 프로세스 실행, 결과·미확정·오류 분리 |
| `configs/preprocessing_samples.pending.json` | 실제 선택 3개와 검토용 구간. 모든 라벨 미확정. 승인된 라벨 파일이 아님 |
| `scripts/requirements-preprocessing.txt` | 기존 PyAV/PyYAML과 NumPy·Pillow 버전 |
| `tests/test_preprocessing.py` | 전처리 테스트 23개. 작은 생성 영상은 테스트 전용 |

입력 JSON에 명시한 최대 3개 구간만 처리한다. CSV의 `path`로 정확히 연결하며 다른 영상은 열지 않는다. 원본·기존 실행 결과를 덮어쓰거나 자동 다운로드하지 않는다.

현재 설정은 `schema_version=1`, `policy_version=draft-0.1`, `time_basis=local_clip_seconds`, `frame_count=16`, `image_size=224`다. 프레임 수는 2~32, 이미지 한 변은 32~512 범위만 허용한다.

구간은 로컬 클립 시작을 0초로 한 `[start_seconds, end_seconds)`이며 최대 10초다. 끝 시각은 포함하지 않는다. 현재 버전에서 정답을 적용하려면 **그 구간 자체의 승인 기록**이 필요하다. 영상 전체 라벨을 잘라낸 구간으로 자동 이전하지 않는다.

### 승인 라벨 입력 조건

원본 CSV와 별도인 입력 목록의 `label_review`에서 다음을 확인한다.

| 항목 | 정답 생성 조건 |
|---|---|
| `status` | `approved`여야 정답 생성. `unreviewed`, `undetermined`, `hold`는 미확정 처리 |
| `label` | 승인 시 `normal` 또는 `accident`. 미확정일 때 반드시 `null` |
| `scope` | `segment`. 영상 전체 판정으로 구간 정답을 대신하면 거부 |
| `start_seconds`, `end_seconds` | 실제 처리할 구간의 시작·끝과 일치 |
| `source_sha256` | 실제 원본 파일과 일치. 다른 버전·재인코딩본에 승인 재사용 불가 |
| `policy_version` | 입력 목록의 라벨 기준 버전과 일치 |
| `basis` | 사람이 확인한 라벨 근거 |
| `reviewer`, `reviewed_at` | 실제 검수자와 `YYYY-MM-DD` 날짜 |

코드는 기록의 누락·형식·대상 파일·구간 일치를 검사한다. 사람이 실제로 검수했는지나 판정이 옳은지까지 자동 증명하지 않는다. 사고 시점·유형을 근거로 복사하거나 status만 바꿔 검수를 대신하면 안 된다.

향후 실제 검수를 완료하면 pending 설정을 별도의 로컬 검수 파일로 복사하고 승인 기록을 입력해 `--plan`으로 지정한다. 현재의 빈 승인 기록을 임의로 채우지 않았으며 원본 CSV는 수정하지 않았다.

## 프레임 처리 방식과 한계

1. 시간값이 유한한 숫자인지, `0 ≤ 시작 < 끝 ≤ 실제 영상 길이`인지 검사한다. 범위 밖 시간을 자동으로 줄이거나 늘리지 않는다.
2. 구간을 16개 같은 길이의 칸으로 나누고 각 중심에 가장 가까운 실제 재생 시각(PTS)의 프레임을 선택한다. 프레임 번호를 평균 FPS로 나누어 선택하지 않는다.
3. 모든 선택 시각은 구간 안에 있고 엄격히 증가해야 한다. 짧은 영상 등에서 서로 다른 16개를 확보할 수 없으면 오류다. 프레임 복제·0 채우기·순서 재배치를 하지 않는다.
4. 전체 화면의 비율을 유지해 224×224 안에 맞추고 남는 공간을 검게 채운다. 중앙 자르기·뒤집기·무작위 변형은 없다.
5. 가공 프레임 PNG와 시간순 모음 그림을 저장한다. 선택 프레임 하나를 원본 해상도로도 저장해 작은 장면과 화면 가장자리를 비교하게 한다.

코덱 때문에 요청 구간의 이전 키프레임부터 일부 앞부분을 디코딩해야 한다. **디코딩한 프레임 전부를 저장하지 않는다.** 제한은 영상당 900개 디코딩 프레임, 2,000개 패킷, 루프 35초/별도 프로세스 45초다. 한도를 넘으면 오류로 기록한다.

미리보기에는 시간·상태를 쓰지만 모델 입력 배열과 개별 프레임 PNG에는 덧쓰지 않는다. 원본 CCTV에 이미 들어 있던 글자·표시는 그대로 남는다.

**화면을 자르지 않았다는 확인과 사고 발생 순간을 충분히 보존했다는 확인은 다르다.** 224픽셀로 줄인 먼 차량·접촉 장면은 식별하기 어려울 수 있다. 16프레임 사이에서 중요한 순간이 빠지거나 구간 앞뒤가 너무 짧을 가능성은 사람이 검수해야 한다. 미리보기만 보고 사고/정상 라벨을 자동 승인하지 않는다.

## 출력과 추적 정보

출력은 원본 데이터 폴더 밖의 **새 폴더**여야 한다. 기존 출력 폴더가 있으면 거부한다. 실패한 샘플의 임시 파일은 정식 결과로 게시하지 않는다.

```text
출력 폴더/
  manifest.json                 모든 결과, 오류, 버전, 해시, 설정
  labeled.json                  승인 구간, 입력 배열 경로, 정답
  unconfirmed.json              미확정 샘플, target=null
  errors.json                   오류와 사유
  labeled/sample_001/           승인 라벨이 있을 때만 생성
    frames.npy                 입력 배열
    frames/000.png ...          처리 프레임
    frames.json                요청/실제 시각, 변환 정보
    preview.png                시간순 모음 그림
    source_reference.png       선택 프레임 하나의 원본 해상도
  unconfirmed/sample_001/       미확정 샘플
    frames/000.png ...          검토용 처리 프레임
    frames.json
    preview.png
    source_reference.png       frames.npy는 생성하지 않음
```

승인 시 입력 배열은 `[T,H,W,C]` 순서, RGB `uint8`, 값 0~255다. 현재 설정이면 `[16,224,224,3]`이다. 정답 순서 `normal=0`, `accident=1`을 함께 저장한다. **구간 하나의 정답**이며 모든 프레임을 사고라고 표시하는 정답이 아니다.

모델을 아직 정하지 않았으므로 모델별 축 변환·평균/표준편차 정규화는 하지 않는다. 배열은 이후 모델 입력 변환에서 사용할 재현 가능한 중간 자료다.

기록하는 추적 정보:

- `source_video_id=sha256:<파일 해시>`: **로컬 원본 클립의 내용 ID**다. 상위 원본 영상 ID·사건 ID로 주장하지 않는다.
- 원본 상대 경로·해시, 요청 시작/끝 초, 선택 프레임의 요청 시각·실제 PTS.
- 범위 선택 근거와 라벨 근거의 분리, 원본 CSV 행·값, 라벨 기준 버전.
- 전처리 버전·코드 해시, 라이브러리 버전, 크기·색상·배치·변환 정보.
- `upstream_original_id`, `source_group_id`, `event_id`: 현재 세 샘플은 근거가 없어 `null`.
- 원본 두 분할: 세 샘플 모두 `test` 보존. 모든 결과의 `training_authorized=false`, `independent_evaluation_ready=false`.

라벨이 승인되어도 사건 그룹·전체 분할의 검증이 끝났다는 뜻은 아니다. 이번 코드에서 test를 train으로 옮기거나 학습·평가용 전체 분할을 만들지 않는다.

승인 라벨 경로의 테스트 영상은 임시로 만든 작은 색상 영상이다. **실제 ACCIDENT 검수 결과나 정상 자료가 아니다.**

추가로 실제 출력 48개 프레임의 크기·시각 순서·구간 내 포함, 참고 이미지 크기, test 분할·null 정답을 확인했다. 원본 CSV·YAML·영상 3개의 SHA-256은 작업 전후 동일했다. 파일 보존 검사와 라벨 정확도 검증은 다르다.

## 남은 사항

- 샘플별 실제 장면·시간 범위를 검수한 승인 라벨이 필요하다. 현재 세 샘플은 모두 미확정이다.
- 정상 자료, 상위 원본·사건 그룹, 정확한 프레임 인덱스 관례는 여전히 미확인이다.
- 미리보기 검수 후 사용할 구간 길이·프레임 수·해상도를 결정해야 한다. test 성능을 보고 조정하지 않는다.
- 모델 학습·다운로드·성능 평가, 전체 프레임 추출·전체 데이터 처리는 수행하지 않았다.
