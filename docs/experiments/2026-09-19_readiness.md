## 2026-09-21 — IID 선택 반영과 A 학습 후보 목록 확인 완료

**사용자가 첫 기준선의 ACCIDENT 분할을 `split_in_distribution`(IID)로 선택했다.** 지리 일반화는 별도 후속 실험이다. 이번에는 기존 점검 코드로 선택을 적용하고 실제 입력 파일·정답·제외 목록까지 확인했다. 모델 학습·평가·다운로드는 하지 않았다. 아래의 ‘평가 방식 미선택’은 이전 실행 이력이다.

QMUL의 세 구간은 기존 원본 해시 `2add2fa0207a9c903e424f76ead3c749bb02a66994c0f4a9e64fc60cc51652bb`와 `local-file-sha256:` 그룹을 공유한다. **정상 원본은 1개**다. 같은 원본을 시간으로 세 토막 냈다고 독립 정상 원본3개가 되지 않는다. 사고 두 파일의 해시는 다르지만 사건 독립성은 미확인으로 보존했다. 이번 `unresolved_accident_keep_together`는 분리하지 말라는 제약이며 ‘같은 사건으로 확인했다’는 정답이 아니다.

원본 사고007~009의 존재·현재 해시와 승인 기록의 일치를 확인했다. QMUL은 사용자가 제공한 정확한 외부 경로에서 파일 존재/340,177,846 bytes만 별도로 확인했고 원본 전체 해시·재생은 다시 검사하지 않았다. 기존 검수된 배열·원본 시각 파일의 해시를 재사용·대조했다. [QMUL 존재 확인](../../artifacts/training-code-check/iid-readiness-audit-20260921-01/qmul-source-receipt.json)에 개인 절대 경로를 저장하지 않았다.

사고 정답/다혜/2026-09-21, QMUL 정상 정답/다혜/2026-09-20, 최신224 품질/다혜/2026-09-21과 정확한 구간을 보존했다. 같은 사고 판정이나 품질 질문을 다시 요구하지 않았다. 원본 주석의 사고 시작 시점은 종료 시점 정답을 뜻하지 않는다. 009의 주석 시각과 프레임/평균FPS 환산 차이 원인은 여전히 미확인이며 승인 구간이나 원본 주석을 바꾸지 않았다.

### A와 B의 준비 상태는 다르다

| 항목 | A: 짧은 가중치 업데이트·저장·재로딩 점검 | B: 다른 원본에서 실제 성능 평가 |
|---|---|---|
| 현재 자료 | 사고2·정상3의 승인 입력 있음. 3구간만 사용하는 안 제안 | 독립 학습/검증 원본과 사건 관계가 아직 준비되지 않음 |
| 이번 실제 확인 | 기존 배열/시간/검수의 연결·공식 IID train 근거·test 제외·입력 목록/해시 | 정상1원본, 사고 사건 관계 미확인, 평가 배정0 확인 |
| 남은 작업 | A 전용 학습 입력 명세와 두 출처 연결, 기존 그룹 검사에 맞는 명시적 A 처리 방식, 공식 가중치 파일 준비, 실행 승인 | 독립 정상/사고 자료·관계 근거, 동일 시간 구성·평가 규칙·검증 분할, 노출되지 않은 최종 평가 자료 |
| 현재 실행 상태 | `held_pending_A_setup_and_approval` | `not_ready` |
| 주장할 수 있는 결과 | 향후 성공해도 학습 코드가 실제 승인 입력으로 작동했다는 증거 | 현재 Precision/Recall/F1·혼동행렬·일반화 성능은 미평가 |

**B 자료가 부족하다는 이유만으로 A 자료를 불가능 처리하지 않는다.** `blocked_by_B_data_shortage=false`다. 다만 이번 A 목록은 학습용 입력 후보 명세이고 기존 학습 `preflight()`를 통과한 실행 manifest는 아니다. 현재 학습 설정은 예전 `pending` 계획, `split_manifest=null`, `pretrained_weights_path=null`을 유지한다. 최신 ACCIDENT/QMUL 두 출처를 실제 학습 진입점에 연결하는 부분도 남아 있다. 그룹 검사를 끄거나 가짜 원본/사건 ID를 채워 실행 가능으로 표시하지 않았다. 이 남은 구현 조건은 독립 평가 자료 부족과 별개다.

**평가 대상도 다르다.** 우리 정답은 사람이 승인한 짧은 구간의 정상0/사고1이다. 공식 사고 시점·위치·충돌 유형 주석의 벤치마크를 재현한 것이 아니다. 공식 IID 분할을 참고하더라도 QMUL 정상 구간과 사람의 이진 구간 정답을 더하므로 ‘공식 ACCIDENT 점수’로 보고할 수 없다. 지리 일반화, 사고 시각·위치 정확도, 사건 단위 탐지 성능을 이번 실험의 구간 분류 결과로 대신하지 않는다. 이번에는 어떤 모델 지표도 계산하지 않았다.

### 추가로 필요한 자료

- **A 입력 목록을 위해 새 정상 영상이 당장 필수인 것은 아니다.** 이미 승인한 QMUL 구간을 이용할 수 있다. A의 짧은 실행 연결과 승인·가중치 준비를 먼저 할 수 있으며 B를 먼저 끝낼 필요는 없다.
- **B 검증 분리를 만들려면:** 최소한 QMUL junction 원본·그 복사/재편집/같은 촬영에서 나온 것이 아닌 정상 원본1개 이상과 검수 구간이 추가로 필요하다. 이것은 분할 구조의 최소 조건이지 충분한 성능 표본 수가 아니다. 실제 평가에는 여러 장소·카메라·시간대의 정상 원본/구간이 필요하다.
- **사고 검증 자료:** 008·009 및 기존 학습 후보와 원본·사건·재편집 관계가 분리됐다는 근거가 있는 IID train 사고 원본1개 이상과 승인 구간을 추가하거나, 현재 사고 원본 관계를 먼저 확인해야 한다. 현재 두 사고 파일을 근거 없이 하나씩 train/validation으로 나누지 않는다. 공식 IID test를 이 부족분 대신 튜닝에 사용하지 않는다.
- 각 자료에 상대 경로, 원출처/이용 조건, 원본 ID·사건 ID 또는 관계를 확인할 근거, 공식 분할이 있다면 해당 원본 열/값, 검수 구간·정상/사고/판단 불가와 근거·검수자·날짜를 기록한다. 없는 공식 분할이나 사건 ID는 미확인으로 둔다. 이미 본 공식 test는 노출 이력을 유지하고 새 비공개 최종 평가 자료와 구분한다.
- 현재 사고는 ACCIDENT, 정상은 QMUL 한 출처라 모델이 사고보다 장소·영상 특성을 구분할 위험이 있다. 이는 아직 측정한 오류가 아니라 설계상의 한계다. 독립 자료를 늘릴 때 양 클래스의 촬영 환경/출처를 다양하게 확보한다. 사고2초/정상6초의 현재 승인 범위는 그대로 두고, B 전에 같은 시간 샘플링 규칙을 정한다. 구간을 자동 확대하거나 새 정답을 붙이지 않는다.

### 이번 코드·제한 시험·실제 출력

기존 `training_data.reviewed_input_readiness()`에 명시적 IID 선택과 A/B별 결과를 추가하고 `compare_candidate_history()`로 파일 키/CSV/버전을 대조했다. 기존 `scripts/train_r3d18.py`의 `inspect_reviewed_inputs()`는 승인 배열/시간 파일 경로·해시와 현재 사고 원본 해시를 결과에 연결한다. `configs/review_readiness.local.json`에는 사용자 선택 원문과 에이전트의 3구간 제안을 구분했다. 기존 전처리·학습 루프·`preflight()` 규칙은 바꾸지 않았다.

프로젝트 루트에서 실제 실행한 기록 전용 명령:

```sh
PYTHONDONTWRITEBYTECODE=1 .venv-model-check/bin/python scripts/train_r3d18.py   --review-readiness configs/review_readiness.local.json   --config configs/train_r3d18.local.json   --output artifacts/training-code-check/iid-readiness-20260921-01
```

위 출력 폴더는 이미 존재하므로 그대로 재실행하면 덮어쓰기 방지로 거부한다. 직접 확인할 때는 출력만 사용하지 않은 새 이름(예: `iid-readiness-user-01`)으로 바꾼다. `--review-readiness`가 있는 이 명령은 학습하지 않는다. 실제 **종료2 / inspection_status=completed / status=held**이며 검사 실패가 아니라 학습 미승인/미준비의 예상 결과다.

**다음 작업 하나(제안만): 공식 평가 방식 선택을 기록한다.** 입력은 위 두 분할 비교와 사용자가 원하는 평가 목적, 출력은 선택한 공식 열·선택 이유·007/008/009의 포함/제외 원칙이다. 한 가지 기준을 명시적으로 선택하되 아직 모르는 사건 관계와 실제 train/validation 배정은 확정하지 않는 것이 완료 기준이다. 이번에는 어느 방식도 자동 선택하지 않았으며, 새 결정/자료 없이 같은 준비 점검을 반복하지 않는다. 학습·새 자료 검색/다운로드·클라우드는 이 제안에 포함하지 않는다.

## 지표와 오류 사례

사고 Precision·Recall·F1·혼동행렬·학습/검증 성능 차이는 **미산출**이다. 0점이나 0으로 채운 혼동행렬로 표현하지 않는다. 정답과 실제 예측이 없으므로 사고 누락·오탐 사례도 아직 없다. 기존 C-2 코드는 제한 학습 루프이며 validation 지표 계산·사건 평가기는 아직 구현되어 있지 않다.

확인한 것은 다음 파일·준비 상태 문제다.

- S0 초기 실행의 sample_001 디코딩 시간 초과: 같은 제한의 재실행에서 읽기 성공. 최초 시간 초과 원인은 미확정이다.
- CSV 프레임 수가 헤더보다 각각 1 작은 차이: 경고 유지, 프레임/시간을 임의 보정하지 않았다.
- 분할 파일·개별 라벨·그룹 근거 없음: 이번에도 held. `split_source_hash_mismatch` 등은 현재 승인 분할 항목이 없는 상태에서 생긴 항목이며 그 자체로 원본 훼손을 뜻하지 않는다. 별도 해시 비교에서 원본은 유지되었다.
- sandbox 조회의 MPS unavailable과 네이티브 C-1 성공은 별도 기록이다. 미지원 오류를 CPU 성공으로 바꾸지 않았다.

## 다음 가장 작은 작업과 완료 기준

**작업 하나: 현재 세 구간의 검수 기록을 별도 파일로 남긴다.** 사용자는 원본과 기존 미리보기를 보고 구간별 판정·근거·작아진 화면의 식별 가능 여부를 전달하면 된다. 원본 CSV나 JSON을 직접 편집할 필요는 없다. [검수할 시각과 입력 양식](../preprocessing_review.md)에 실제 세 구간이 있다.

완료 기준은 세 구간 각각이 사고/정상/판단 불가/재검토 중 하나와 근거·검수자·날짜를 갖고 원본 해시·시작/끝 초에 연결되는 것이다. 확정 가능한 정답만 배열과 함께 읽고, 판단 불가·재검토는 별도로 보존한다. 이 작업으로 test 자료를 train에 옮기지 않는다. 아직 관찰 결과가 제공되지 않았으므로 이번에는 정답 파일을 채우지 않았다.

그 다음 실제 학습 전에 필요한 자료:

1. 현재 test와 원본·사건이 겹치지 않는 **학습용 사고 구간과 검수된 정상 구간**. 정상은 주석 누락·사고 이전이라는 이유만으로 만들지 않는다.
2. 학습과 원본·사건·재편집 그룹이 분리된 validation 자료. 두 클래스가 있어야 오탐·누락을 함께 살펴볼 수 있다. 제공 분할의 train 안에서 그룹 기준으로 떼어내거나 별도 출처를 검수한다.
3. 원본 출처/ID, 사건 ID, 재편집 그룹과 분할 근거. 같은 영상의 여러 구간은 한 분할에 묶는다. 정상 영상도 출처·촬영 세션 등 그룹 근거가 필요하며 가짜 사고 ID를 붙이지 않는다.
4. 구간 라벨 정책 및 16프레임·224픽셀 입력의 검수 승인. 해시·버전과 연결해 기록한다.

정상 1개·사고 1개는 루프 연결을 검사할 수 있는 최소 예시일 뿐 성능 평가 자료로 충분하지 않다. 현재 plan 최대 3개 제한을 유지한 상태에서 훈련·검증 성능 실험을 주장하지 않는다. 본격 규모와 제한 확장은 자료 수·독립 그룹 수를 확인한 뒤 별도 승인 대상이다.

## 이후 비교 실험 제안 하나 — 아직 실행하지 않음

자료와 기준 모델 결과가 준비된 뒤 **학습률만 0.001 → 0.0003으로 변경**하는 실험을 제안한다. 한 번에 가중치를 덜 바꾸면 검증 결과가 더 안정적인지 확인하려는 가설이며 현재 문제 원인이 큰 학습률이라는 증거는 없다. 개선을 약속하거나 설정을 미리 바꾸지 않았다.

| 항목 | 기준 실행 | 비교 실행 |
|---|---|---|
| 학습률 | 0.001 | 0.0003 |
| 학습할 층 | head | 동일 |
| 입력 | 승인된 16프레임·224×224·전체 화면 유지 | 동일 |
| 기타 | 동일 초기 가중치·fc 초기화 seed, batch 1, momentum 0.9, 같은 학습량 | 동일 |
| 자료·분할 | 승인된 같은 파일 목록·해시·구간·사건 그룹 | 동일 |

기준 실행과 비교 실행을 동일한 시작점에서 각각 시작한다. 기준 모델을 더 학습한 결과와 새 모델을 비교하여 학습량 차이를 학습률 효과로 혼동하지 않는다. 짧은 20 step은 실행 확인용이므로 이 제한 시험만으로 우수 모델을 고르지 않는다.

평가 코드를 준비할 때 사고를 양성으로 한 구간별 Precision(사고 예측 중 실제 사고), Recall(실제 사고 중 찾아낸 비율), F1, 혼동행렬과 양쪽 클래스 수를 기록한다. 학습/검증 비교도 증강 없는 동일한 평가 방식으로 한다. 임계값 선택 규칙은 실험 전에 정하고 **기준 모델의 validation에서 결정한 값을 이 학습률 비교 동안 고정**한다. 테스트에서 임계값을 고르지 않는다. 분모가 0인 지표는 미정으로 표시한다.

사건 단위 평가는 여러 구간의 예측을 어떤 규칙으로 한 경보에 묶을지, 실제 사고와 허용 시간차·중복 경보를 어떻게 셀지 정해야 한다. 구간 F1을 사건 탐지 F1로 이름만 바꾸지 않는다. 최종 test는 모델·임계값·평가 규칙을 확정한 뒤 별도로 사용한다.

## 학습 범위·속도·시간 계획

이번에는 층을 늘리지 않았다. 이후 특징 추출부를 풀어 학습한다면 새 입력·optimizer·학습 범위에서 MPS 순전파/역전파/업데이트와 메모리를 소수 step으로 다시 확인한다. **C-1은 실제로 전체 층을 시험했지만 112픽셀 난수·momentum 없는 SGD였다.** 이것이 224픽셀·사전학습·새 범위의 검증을 대신하지 않는다.

현재 실제 영상 학습 시간은 없어서 “너무 느리다”고 판단할 근거도 없다. 준비가 되면 디코딩/입력 변환, GPU 계산, 역전파, 저장·재로딩 시간을 나누어 측정한다. 최초 실행과 후속 step도 구분한다.

| 대안 | 적용 조건·비교할 점 | 현재 상태 |
|---|---|---|
| 특징을 한 번 저장하고 fc만 반복 학습 | 특징 추출부 가중치·BatchNorm 모드·전처리·프레임 선택이 모두 고정일 때. 원본 해시·구간·실제 프레임 시각·모델 해시·전처리 버전을 캐시 키에 포함. 층을 풀거나 입력이 달라지면 재계산 | 미구현·미측정. 저장 공간도 실측 후 제안 |
| CPU 별도 실행 | MPS 미지원 연산이나 오버헤드가 확인되면 동일 작은 입력으로 장치를 명시해 비교 | 전체 R3D CPU 학습 시간 미측정. 자동 전환 없음 |
| Colab GPU | 로컬 호환성·속도·메모리 실측에서 필요성이 확인되면 공통 코드로 비교 | 미실행. 업로드·장시간 자원 사용은 별도 승인 |

현 설정의 후속 제한 실행은 최대 20 step 또는 학습 작업 프로세스 300초다. 프로세스 한도에는 모델 초기화·저장·재로딩도 포함되며 준비용 디코딩은 영상별 최대 45초로 별도다. 이는 실행 상한이고 완료 예상 시간은 아니다. 공식 가중치가 필요하면 약 127.4 MB 다운로드를 먼저 승인받는다.

긴 학습의 예상 시간은 아직 산정할 수 없다. 실제 입력으로 준비 시간, step 중앙값·상위 지연, 검증 및 저장 시간을 측정한 뒤 `epoch 수 × ceil(학습 구간 수 / batch 크기) × step 시간 + 준비·검증·저장 시간`으로 범위를 제시하고 승인받는다. C-1의 0.920초/5.909초를 실제 데이터 학습 시간에 그대로 곱하지 않는다.

## 이번 재실행 명령과 산출물

프로젝트 루트에서 실제로 실행했다.

```bash
.venv-model-check/bin/python scripts/train_r3d18.py --check-only \
  --output artifacts/training-code-check/readiness-20260919-01
```

결과: `status=held`, `selected_segments=3`, `approved_segment_labels=0`, `train_segments=0`, `training_run=false`, `weights_downloaded=false`. 종료 2는 학습 준비 부족을 나타내며 이 사례에서는 예상한 결과다. 파일 손상이나 모델 학습 실패로 해석하지 않는다.

출력 폴더에 config/preflight/summary와 명령 출력 `command.log`, 실측 시간·표본 수·원본/코드 해시를 기록한 `audit.json`을 남겼다. 재실행에는 새 출력 폴더 이름을 사용한다. `--check-only`는 라벨/분할/파일 검사이며 GPU·공식 가중치 로딩 시험이 아니다.

이번 변경은 설명 문서와 실험 기록뿐이다. 모델·전처리 코드·설정·원본 자료는 그대로이며 해시를 대조했다. 새 코드 변경이 없어 단위 테스트를 반복 실행하지 않았고, 기존 80개 통과 기록과 이번 준비 검사 결과를 구분했다. 학습·추출·가중치 다운로드·클라우드 업로드·서비스 구현은 하지 않았다.
