## 공유할 설명

> 사고 영상 3개에서 검토용 2초 구간을 하나씩 정했습니다. 각 구간을 균등한 시간칸 16개로 나누고 실제 재생 시각이 가까운 프레임을 골랐습니다. 화면을 자르지 않고 비율을 유지해 224×224에 맞춘 뒤 빈 공간을 검게 채웠습니다. 총 48장의 프레임과 시간순 미리보기를 저장했고 원본과 연결되는 파일 해시·구간 시각도 남겼습니다. 이후 다혜가 세 구간을 사고로 확인하여 별도 검수 기록을 만들었습니다. 이 승인 정답을 연결한 배열 생성은 아직 실행하지 않았으며, 기존 미리보기 출력은 검수 전 상태로 보존했습니다.

## 실제 영상에 적용한 것

| 단계 | 의미 |
|---|---|
| 영상 선택 | 준비된 real 영상 3개만. 전체 다운로드·합성 자료 사용 없음 |
| 구간 선택 | CSV 사고 시점 앞뒤 1초를 검토 위치로 지정. 확정된 사고 시작/끝이 아님 |
| 프레임 선택 | 실제 재생 시각 PTS 기준 16개. 평균 FPS로 프레임 번호를 추측하지 않음 |
| 크기 조정 | 전체 화면을 유지한 224×224. 중앙 crop·반전 없음 |
| 순서 확인 | 실제 시각이 앞에서 뒤로 엄격히 증가하는지 검사 |
| 저장 | PNG, 시간표 JSON, 모음 그림, 선택 프레임 하나의 원본 해상도 이미지 |
| 정답 처리 | 세 구간 모두 미검수 → `target=null`. 미주석을 정상으로 바꾸지 않음 |

영상 압축 때문에 앞선 키프레임부터 일부 디코딩하지만 선택 프레임만 저장했다. 모든 프레임을 이미지로 펼친 작업이 아니다.

| 샘플 / 원본 파일 | 검토 구간(초) | 첫~마지막 저장 프레임 시각(초) | 저장 수 |
|---|---|---|---|
| 001 / `-9oifpjUxxM_00.mp4` | 7.533~9.533 | 7.600~9.467 | 16 |
| 002 / `-PpBteU0p3Q_00.mp4` | 2.292~4.292 | 2.375~4.250 | 16 |
| 003 / `-SNFUobKjoM_00.mp4` | 12.533~14.533 | 12.600~14.467 | 16 |

첫 영상 원본은 1620×1080, 나머지는 1280×720이다. 서로 다른 크기를 모델이 받을 **가로 224 × 세로 224픽셀**로 통일했다. 원래 화면의 비율은 유지하고 남는 자리를 검게 채웠다. 화면을 정사각형으로 찌그러뜨리거나 가운데만 잘라낸 것이 아니다.

| 원본 크기(가로×세로) | 화면을 줄인 크기 | 검은 여백 | 최종 크기 |
|---|---|---|---|
| 1620×1080 | 224×149 | 위 37, 아래 38픽셀 | 224×224 |
| 1280×720 | 224×126 | 위·아래 각 49픽셀 | 224×224 |

224는 영상 길이나 프레임 수가 아니다. 한 장의 이미지 크기다. 픽셀이 줄어 작은 차량이나 접촉 장면이 잘 안 보일 수 있으므로 원본과 미리보기를 비교해야 한다. 실제 저장된 `frames.json`의 변환 기록과 일치하는 크기다.

## 모델에 넣기 위한 숫자 배열 변환

다음 단계는 **앞으로 구간별 검수가 승인되어 학습용 배열을 만들었을 때** 적용할 코드다. 지금 실제 세 영상에는 이 단계를 적용하지 않았다.

1. `[시간,높이,너비,색상] = [16,224,224,3]`은 시간순 사진 16장이고, 사진마다 세로·가로 224픽셀, 각 픽셀에 빨강·초록·파랑(RGB) 값 3개가 있다는 뜻이다.
2. R3D-18에 맞춰 숫자를 담는 축의 순서를 `[색상,시간,높이,너비] = [3,16,224,224]`로 바꾼다. 사진의 시간순서·색 순서·방향은 그대로다. 한 구간씩 처리하면 앞에 묶음 크기 1이 붙어 `[1,3,16,224,224]`가 된다.
3. `float32`는 소수 계산을 할 수 있는 숫자 형식이다. 원래 색 값은 0~255 정수인데, 255로 나눠 0~1로 만든다. 예를 들어 128은 약 0.502가 된다.
4. 채널 정규화는 빨강·초록·파랑 값 각각에서 정해진 평균을 빼고 정해진 표준편차로 나누는 것이다. 사전학습 모델이 사용한 입력 숫자의 기준에 맞춘다. **정규화까지 끝난 값은 음수나 1보다 큰 값일 수 있다.** 사고 점수나 정답으로 변환하는 작업이 아니다.

정규화 상수와 모델 입력 축 순서는 [Torchvision 0.25 R3D-18 문서](https://docs.pytorch.org/vision/0.25/models/generated/torchvision.models.video.r3d_18.html)와 대조했다. 우리 공간 전처리는 화면 전체를 남기는 224×224이고, 공식 기본 변환의 112×112 중앙 자르기와는 다르다. 같은 전처리 전체를 그대로 사용했다고 표현하지 않는다.

이 배열 변환은 작은 테스트 배열을 넣고 다시 원래 형태·값으로 되돌려 확인했다. **실제 영상 미리보기 48장을 만든 것**과 **실제 구간·승인 정답을 학습 로더에서 읽은 것**은 다르며, 후자는 아직 미실행이다. C-1의 112×112 입력은 컴퓨터가 만든 무작위 숫자다. 실제 224×224 미리보기를 다시 줄인 입력이 아니다.

## 일부 디코딩은 무엇인가

디코딩은 MP4 안의 압축된 정보를 컴퓨터가 볼 수 있는 프레임 이미지로 푸는 작업이다. 일부 디코딩은 영상 전체 대신 제한한 부분만 읽는다는 뜻이다.

- S0 파일 점검: 영상의 몇 위치에서 프레임을 조금 읽어 디코더가 작동하는지 확인했다. 압축 기준점인 앞선 키프레임에서 읽기 시작하므로 요청한 시각과 정확히 같은 장면이라는 보장은 없다.
- 구간 전처리: 선택한 2초 구간에서 저장할 16장을 고르기 위해 필요한 앞부분도 읽었다. 실제 디코딩 수는 영상별 143/64/183장이지만 저장한 처리 프레임은 각각 16장이다.
- 테스트 코드: 임시로 만든 작은 영상과 손상 파일을 이용해 읽기 성공·실패 처리를 검사했다. 이 테스트가 실제 사고 장면을 판독했다는 뜻은 아니다.

일부 읽기 성공으로 영상 전체가 손상 없이 재생된다거나 사고를 인식할 수 있다고 결론 내리지 않는다.

프로젝트 루트에서 기존 결과를 연다. 이 명령은 새 추출이나 학습을 하지 않는다.

```bash

```

각 sample 폴더에서 다음을 본다.

| 파일 | 볼 내용 |
|---|---|
| `preview.png` | 왼쪽→오른쪽, 위→아래로 시간순. actual은 실제 시각, requested는 선택 목표 시각 |
| `frames/000.png` 등 | 시간 글자를 덧쓰지 않은 실제 처리 프레임 |
| `frames.json` | 전체 시각 목록, 배열 모양, 변환 방식, target=null |
| `source_reference.png` | 선택 프레임 하나의 원본 해상도. 원본 전체 영상의 대체 자료는 아님 |

원본 영상 하나와 미리보기를 같이 열려면:

```bash
open data/local/accident/real_videos/-9oifpjUxxM_00.mp4
open artifacts/preprocessing/s1-samples-02/unconfirmed/sample_001/preview.png
```

원본을 먼저 보고 7.533~9.533초 부근과 미리보기를 비교한다. 다른 두 파일도 표의 시각으로 비교한다.

1. 지정 구간 안에서 실제 접촉·충돌 발생 과정이 보이는가?
2. 필요한 순간이 구간 시작/끝 밖으로 잘렸거나 선택 프레임 사이에서 빠지지 않았는가?
3. 작아진 화면에서도 사고 위치를 구별할 수 있는가?
4. 원본과 같은 움직임 순서인가? 애매하면 판단 불가로 남겼는가?

파일명·시작/끝 초·판정·실제 보인 장면·검수자·날짜를 기록한다. 사고 시점 숫자가 구간 안에 있다는 이유만으로 승인하지 않는다. 현재 세 영상은 공식 test이므로 이 검수가 곧 학습 사용 승인은 아니다.

## 내가 정답을 직접 넣어야 하나

**해당 구간에 무엇이 보이는지는 사람이 확인해 주어야 한다. JSON이나 CSV를 직접 편집할 필요는 없다.** 아래 항목을 자연어로 전달하면 그 내용을 별도 검수 기록으로 옮길 수 있다. 원본 CSV·영상에는 손대지 않는다. 모르는 항목은 미확인으로 남긴다.

현재 코드는 “선택한 짧은 구간에 사고 발생 장면이 포함됐는가”를 다룬다. 라벨 정책 초안의 최초 제안이었던 “영상 전체의 사고 여부”와 단위가 다르다. 따라서 “30초 영상 전체에는 사고가 있다”는 확인은 존중하되, 선택한 2초 안에서 실제 사고 발생이 보이는지는 한 번 더 확인해야 한다. 현재 `draft-0.1` 기준과 구간별 검수는 아직 확정 기록이 없다.

| 검토할 구간(클립 시작이 0초) | 판정 | 보인 장면·시각 / 미리보기 식별 가능 여부 |
|---|---|---|
| sample_001: 7.533~9.533초 | 미기입 | 미기입 |
| sample_002: 2.292~4.292초 | 미기입 | 미기입 |
| sample_003: 12.533~14.533초 | 미기입 | 미기입 |

다음 형식으로 세 구간 각각 적으면 된다. 대괄호는 실제 관찰로 채울 자리이며 정답 예시가 아니다.

```text
대상: sample_001 / -9oifpjUxxM_00.mp4
판정 범위: 7.533초 이상, 9.533초 미만
판정: [사고 / 정상 / 판단 불가 / 구간 재검토 중 선택]
근거: [실제로 보인 장면과 대략적인 시각]
224픽셀 미리보기에서도 식별 가능: [예 / 아니오 / 미확인]
접촉 순간·시간순서 확인: [관찰 결과, 필요하면 구간 조정 제안]
검수자 / 날짜: [직접 기입]
적용한 라벨 기준: [draft-0.1의 구간 기준 동의 여부 또는 수정할 내용]
```

사고는 구간 안의 실제 충돌·전복 발생 과정이 보일 때, 정상은 그 구간 전체를 판독할 수 있고 사고 발생이 없음을 확인했을 때 기록한다. 가림·저화질·경계 잘림은 판단 불가 또는 재검토로 남긴다. 사고 후 정차 장면만 있는 구간은 현 초안에서 사용 보류다. 아직 보지 않은 것은 미검수다. 미검수·판단 불가·재검토는 정상 0으로 바꾸지 않는다.

검수할 구간의 시작·끝과 **사고 자체의 시작·끝 시각**은 다르다. 지금 필요한 것은 지정 구간의 포함 여부와 근거이며, 모르는 사고 종료 시각까지 억지로 만들 필요는 없다. 모든 프레임에 0/1을 직접 붙이는 작업도 아니다. 원본에서는 사고가 보이지만 16장 미리보기에서는 놓쳤다면 그 사실을 기록하고 해당 입력 사용을 보류한다.

**세 구간을 모두 사고로 검수해도 학습 준비는 완료되지 않는다.** 세 원본 모두 공식 test이며, 별도의 학습용 사고·정상 구간과 원본/사건이 분리된 검증 자료가 필요하다. 이 test 샘플의 예측 결과로 프레임 구성·학습률·판정 임계값을 골라서는 안 된다.

저장 상태를 숫자로 확인하려면:

```bash
.venv-model-check/bin/python - <<'PY'
import json
from pathlib import Path
root = Path('artifacts/preprocessing/s1-samples-02')
manifest = json.loads((root / 'manifest.json').read_text())
for sample in manifest['samples']:
    frames = json.loads((root / sample['frames_metadata_path']).read_text())
    times = [frame['actual_seconds'] for frame in frames['frames']]
    print(sample['sample_id'], 'target=', sample['target'],
          'frames=', len(times), 'shape=', frames['array_shape'],
          'ordered=', all(b > a for a, b in zip(times, times[1:])))
PY
```

현재 결과는 샘플별 `target=None`, `frames=16`, `shape=[16,224,224,3]`, `ordered=True`다. None은 정상 0이 아니다. 이 검사는 파일·순서를 확인하며 사고 정답을 판정하지 않는다.

같은 pending 구간의 미리보기를 재생성하려면 새 출력 폴더 이름을 쓴다.

```bash
.venv-model-check/bin/python scripts/preprocess_samples.py \
  --data-root data/local/accident --plan configs/preprocessing_samples.pending.json \
  --output artifacts/preprocessing/my-review-01
```
