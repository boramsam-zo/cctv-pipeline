# CCTV 프로젝트 PRD 작성 프롬프트

작성일: 2026-09-26 · 상태: 사용자 답변 반영 완료 · 목적: FE·BE·클라우드 개발 착수의 공통 기준

## 사용 방법

아래 프롬프트를 프로젝트 문서를 읽을 수 있는 대화에 붙여 넣는다. 문서에 접근할 수 없다면 현재 상태 요약과 사용자 답변을 함께 제공한다. 이 프롬프트는 PRD 작성용이며, 이번에 실제 PRD 개정·개발·모델 실행까지 요청한 것은 아니다.

### 이번 대화에서 확인한 선택

| 결정 | 현재 상태 |
|---|---|
| PRD 용도 | 사용자 확정: 팀 개발·발표용 전체 서비스 PRD. 이후 클라우드 구조 설계와 FE·BE 구현의 공통 기준 |
| 대상 사용자 | 사용자 확정: CCTV 관제 담당자, 프로젝트 팀의 영상 검토자, 경찰·사고 대응 담당자 모두 |
| 첫 완성본 범위 | 사용자 확정: 사고 후보 탐지·영상 확인 + VLM 장면 설명 + RAG 문서 안내·보고 초안 |
| 업무 배정 | 사용자 요청으로 개인별 역할·업무 분담은 작성하지 않음 |
| 일정 | 마감일 미제공. 이번 프롬프트 완성의 선행 조건으로 삼지 않음 |
| 후속 모델 결정 | YOLO 사용 확정. 사고 분류 모델은 미정. X3D-M을 확정하지 않음 |
| 후속 클라우드 방향 | AWS로 쉽게 웹·API·저장을 구성하고 GPU는 Colab/외부 환경 사용 가능. AWS 예산·크레딧 없음이라는 답변. 자원 생성은 미실행 |

서비스 사용자의 세 역할은 유지하고, 개발자 개인별 업무 배정은 제외한다. 세 역할을 대상으로 삼는 결정은 역할별 3개 화면·로그인·실제 기관 전송을 확정한 것이 아니다. 사용자별 권한과 전달 흐름은 PRD에서 제안·확인한다. 전체 프로젝트 인원·마감·예산은 대상 사용자 수에서 추정하지 않는다.

4. PRD 구성
다음 순서로 작성하되, 중복 설명과 불필요한 표는 줄인다.

A. 한 페이지 요약
   제품 한 문장, 해결할 문제, 주 사용자, 첫 완성본의 핵심 가치,
   포함 범위, 완료 기준, 가장 큰 미정 사항을 정리한다.

B. 사용자와 문제
   어떤 상황에서 어떤 불편을 겪고, 현재 어떻게 처리하며,
   서비스가 어떤 행동을 도와주는지 설명한다.
   실제 인터뷰·관찰 근거와 아직 검증하지 않은 문제 가설을 구분한다.
   세 역할별 목표 / 사용하는 상황 / 입력·확인할 정보 / 수행 행동 / 결과물 /
   다른 역할에 넘기는 정보를 표로 정리한다.
   관제의 후보 검토, 팀의 모델·근거 검증, 경찰/대응 담당자의 확인된 정보 검토를
   역할 구분의 제안으로 출발하되 실제 업무 절차라고 단정하지 않는다.

C. 범위와 우선순위
   첫 완성본 필수 / 후속 검토 / 제외 항목을 표로 정리한다.
   각 항목에 이유와 사용자 결정 또는 제안 상태를 표시한다.
   탐지·영상 확인·VLM·RAG·보고 초안은 첫 완성본에 배치한다.
   실시간 입력과 실제 기관 전달은 확정되지 않은 후속 검토 항목으로 다룬다.
   의존성은 따로 확인한다. PRD에 포함한 목표와 지금 구현된 상태를 구분한다.

D. 핵심 사용 흐름
   영상 선택 → 분석 상태 확인 → 의심 구간 확인 → 원본 근거 검토 → 결과 활용의
   정상 흐름을 사용자 관점에서 설명한다.
   사고 후보와 원본 근거 → VLM의 관찰 설명 → RAG 문서 근거 → 보고 초안 →
   사람 검토의 연결을 포함하고, 역할 사이의 인계 지점을 표시한다.
   후보 영상은 설명·검색이 끝나기 전에도 확인할 수 있는 흐름을 제안한다.
   후보 없음, 일부 미분류, 분석 실패, 설명·검색 실패의 흐름도 적는다.
   분석에 실패한 영상을 '사고 없음'으로 보여주지 않는다.
   저장 결과 시연, 새 녹화영상 분석, 실제 실시간 입력을 정확히 표시한다.

E. 기능 요구사항과 인수 기준
   기존 docs/requirements.md의 ID를 확인해 관련 항목에 연결한다.

   완료 조건은 입력·사용자 행동·관찰 가능한 결과로 쓴다.
   예: '후보 구간을 선택하면 해당 원본의 대응 시각을 재생할 수 있다.'
   이 예시는 제안이며 현재 구현 사실로 표시하지 않는다.

F. 입력·출력과 기능 간 연결
   영상/카메라 식별자, 원본 상대 시각, 후보 구간, 근거 참조,
   분석 상태, 모델 버전, 사람 확인 결과 등 필요한 정보만 정리한다.
   VLM에는 실제 장면·시각 입력과 관찰 설명 출력을 명시한다.
   RAG에는 문서 출처·개정일·적용 범위·근거 부족 응답을 명시한다.
   일반인용 공개 안내와 기관 내부 업무 절차를 구분하고,
   확보하지 않은 기관 매뉴얼이나 관할 연결표는 필요한 자료로 표시한다.
   영상에서 관찰한 내용, 문서 안내, 사람이 확인한 사실을 구분한다.
   확인하지 않은 위치·촬영 절대시각·관할·피해·과실을 생성하지 않는다.

G. 성공 지표와 평가 계획

   미탐/Recall, 정상 오탐, 탐지 지연을 중심으로 하되
   영상 전체 분류, 시간 창 분류, 사건 탐지를 서로 다른 평가로 다룬다.
   시간당 오탐은 경보 병합 규칙과 정상 영상 시간,
   지연은 기준 사고 시각과 탐지 시각의 정의가 필요함을 반영한다.
   미분류·실패 수와 비율을 함께 보고한다. 처리한 수와 채점한 수를 구분한다.
   VLM·RAG의 관찰 근거 일치, 검색 근거 적합성, 인용 정확성,
   근거 부족 시 응답과 사용자 검토 시간을 별도로 평가한다.
   확인된 숫자 합격선이 없으면 미정으로 둔다.

   실험 결과는 동일 평가 목록·정답·판정 기준인지 확인한 뒤 비교한다.
